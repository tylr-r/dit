## Diagnosis and migration

The review compared iOS and shared code against the May release commit `7f6b0ce`. All six findings were addressed: shared animation easing, full answer-card pressable width, Conversation transcript replay, audio-only retry, returning-user tutorial Back, and continuous prosign playback/input. Replay fix: `bcac574`.

Build 1's release log ends in `ARCHIVE SUCCEEDED` and `EXPORT SUCCEEDED`; its simulator log ends in `BUILD SUCCEEDED`. Both emit an `RNFBAppCheck` precompiled-module diagnostic. Relaunching the installed simulator binary reproduced the crash in `UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`. The generated project and archived app lacked `UIApplicationSceneManifest`; the archive used the iOS 27.1 SDK.

[Expo's supported scene lifecycle](https://github.com/expo/fyi/blob/main/ios-scene-lifecycle.md) is now used through Expo **58.0.14** and React Native **0.88.0**. Generation produces SceneDelegate.swift, its app-target membership, and the scene manifest. The local Firebase plugin initializes App Check and Firebase exactly once before Expo starts the scene. It imports App Check directly in Swift and removes the old bridging-header import. The successful simulator build contains no compiler errors or old precompiled-module diagnostic.

The migration also aligns React and its renderer to 19.3, replaces removed React Native APIs, updates component ref types, and uses iOS 16.4 as the deployment target. Web shares React 19.3 for consistent hook resolution in the hoisted workspace. Expo's upstream Device Hub support replaces the local Expo 55 CLI patch. Existing icon and DOM WebView packages are declared explicitly so the supported versions resolve reliably.

Native compilation then exposed Storybook's incompatible automatic Gesture Handler 2.x peer. Its existing native peers are now explicit devDependencies with compatible versions. Metro's obsolete package-exports override also blocked expo-asset from resolving a React Native entry point; the Expo default resolves it. See [native compatibility notes](../NATIVE_IOS.md#expo-58-scene-lifecycle-migration) for the intentional Gesture Handler version exception.

## Device build and archive

The selected installation is `/Applications/Xcode.app/Contents/Developer`, reporting **Xcode 27.1 (27A9275)**.

The local native project and pods have been regenerated. To build and install on a connected, unlocked iPhone, run from the repository root and select the phone when prompted:

```bash
pnpm run lint
DIT_ENABLE_DEV_CLIENT=0 pnpm --filter @dit/ios ios --device --configuration Release --no-build-cache
```

Expo writes the native build output to `apps/ios/.expo/xcodebuild.log`. Confirm the installed app opens, then check the flows below. After device checks, create the App Store archive:

```bash
pnpm run lint
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer pnpm --filter @dit/ios app-store:build --check 2
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer pnpm --filter @dit/ios app-store:build 2 > /private/tmp/dit-ios-release-build.log 2>&1
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer pnpm --filter @dit/ios app-store:upload --validate
```

The archive command regenerates the native project, installs pods, archives Release, and exports an IPA. It excludes dev-client modules and restores the package file on exit. `--check` verifies toolchain/version inputs only; the scene-manifest guard runs after generation during the real archive command.

- Log: `/private/tmp/dit-ios-release-build.log`
- Archive: `apps/ios/build/app-store/Dit.xcarchive`
- Export directory: `apps/ios/build/app-store/export`

The existing archive and IPA are still build 1. Do not use them for submission or as evidence that the migration builds.
