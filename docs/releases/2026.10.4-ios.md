- App Store Connect was checked directly: **2026.5.31 (1)** is live. No newer version or build was present. App ID: `6758277876`.

- Release scripts check the toolchain before changing files, reject invalid build numbers, use the frozen lockfile, and reject an IPA whose bundle/version/build differs from the prepared configuration. `--check` and `--validate` support preparation without archiving or uploading.

## Release steps

1. Release Xcode installation and first-launch setup are complete. Continue with the checks and archive below.
2. From the repository root, run:

   ```bash
   pnpm run lint
   DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer pnpm --filter @dit/ios app-store:build --check 1
   DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer pnpm --filter @dit/ios app-store:build 1 > /private/tmp/dit-ios-release-build.log 2>&1
   DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer pnpm --filter @dit/ios app-store:upload --validate
   ```

   The build regenerates the ignored native project with `--clean`, installs pods, archives Release, and exports an IPA. It temporarily excludes dev-client modules and restores the package file on exit. Build log: `/private/tmp/dit-ios-release-build.log`. Archive: `apps/ios/build/app-store/Dit.xcarchive`. IPA directory: `apps/ios/build/app-store/export`.

3. Review the privacy-page changes, deploy them through the normal web release workflow, and verify `https://practicedit.com/privacy` shows the new disclosure. Check App Store privacy answers against actual Firebase/Gemini processing and retention before submission. Do not assume that absence of account sync means messages never reach Google.
4. When ready to upload the binary, run:

   ```bash
   DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer pnpm --filter @dit/ios app-store:upload
   ```

   Existing App Store Connect API credentials were verified for read access. The upload script loads the local iOS `.env`; the signing key exists in Apple's default local key directory. No credentials are committed. If build 1 is uploaded and another archive is needed, use build 2 and keep Expo's build number in sync.

5. Install the processed build through TestFlight and perform the device checks below. Create the **2026.10.4** App Store version, select the validated build, review the two metadata drafts, verify age-rating/privacy answers and screenshots, and submit when satisfied.
6. When the iOS update ships, move only its entries from Unreleased into a dated iOS release section in `docs/CHANGELOG.md`. Leave unreleased web entries in place.

## Device checks before submission

- Complete one two-way QSO on a physical device while signed out. Release App Attest has not been verified on hardware; the registered simulator debug token does not cover it. Confirm the sharing prompt appears for both starting directions, Cancel stays silent, and Allow permits the contact.
- Confirm reply decoding, Send, reception, Pause/Resume/Replay, optional copy checking, short Reveal buttons, and End QSO. The reply key should stay at the bottom and the background should keep moving throughout the contact.
- Test Listen Words and Q codes: options hidden during audio, correct-answer feedback, Q-code meanings after answering, and Next.
- Test Custom text playback with pause/resume and the copy keyboard. Check that copy remains local and does not affect scores.
- Verify a Practice hint leaves the attempt unscored, Settings Test sound follows speed/pitch, and recognition progress remains intact after upgrading.
- Check a small iPhone and iPad for text/keyboard clipping. Check audio, haptics, Reduce Motion, VoiceOver, optional sign-in, widgets, and reminders.
