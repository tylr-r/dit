## Build the archive

Run from the repository root:

```bash
pnpm run lint
pnpm --filter @dit/ios app-store:build --check 1
pnpm --filter @dit/ios app-store:build 1 > /private/tmp/dit-ios-2026.10.25-build.log 2>&1
```

The explicit `1` keeps this archive at the prepared build number instead of using the script's default increment. The command regenerates the native project, installs pods, archives Release, and exports an IPA with dev-client modules excluded. It does not install on a phone or upload anything. The `--check` invocation only checks toolchain/version inputs and does not build or change files.

- Log: `/private/tmp/dit-ios-2026.10.25-build.log`
- Archive: `apps/ios/build/app-store/Dit.xcarchive`
- Export: `apps/ios/build/app-store/export/Dit.ipa`

The existing export predates this candidate. Do not use it. The upload script checks bundle, version, and build against the prepared configuration before contacting Apple.

After a successful archive, validate the new export:

```bash
pnpm --filter @dit/ios app-store:upload --validate
```

Validation checks the IPA with Apple; it does not upload it for TestFlight or submit it for review. If a binary has already been uploaded and needs replacing, increment the build number and use that number consistently in the config and archive command.
